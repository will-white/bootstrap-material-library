Every control, every foundation, every modern-CSS gate

This page is the whole of m3x rendered by m3x. The components are grouped the way Material 3 groups them — actions, communication, containment, navigation, selection, text inputs — and each entry names its .m3-* class and the Bootstrap class that renders the same component from the same mixin. The platform section demonstrates the modern CSS the library is built on, each with a badge that reports what your browser is doing with it right now. There is no JavaScript here beyond the four controls in the header.

Change the seed, scheme, contrast level or density in the header and the entire page re-themes: every colour below is derived from the seed at build time and, where relative color syntax is available, recomputed live from --md-seed.

Foundations

Four tiers: a seed generates the reference palettes, the palettes resolve to M3’s system roles, the roles feed per-component tokens, and components read those. Everything on this page moves when the seed, scheme or contrast level moves.

Tonal elevation

M3’s other elevation channel, and the only consumer of the --md-sys-color-surface-tint role: the tint composited over surface at an opacity that grows with the level, from Compose’s (4.5 · ln(dp+1) + 2)% at M3’s 1 / 3 / 6 / 8 / 12 dp. m3x’s own components don’t use it — they take their fills from the surface-container roles, which is what current M3 does — but the role is real, so .m3-surface-tint-0…-5 and m3.surface-tint() apply it. Motion

M3’s easing set and duration ramp, plus the Expressive spring tokens. Each spring is resolved at build time into a linear() curve sampled from the damped-oscillator solution, with its settle time as the duration; a cubic-bézier stand-in ships for browsers without linear(). Every transition on this page sits behind prefers-reduced-motion: no-preference.

Spacing and density

One spacing scale (--m3-sys-space-1…-8: 4, 8, 12, 16, 24, 32, 48, 64px) and one density knob. Density is the sole vertical authority: every control height is height + density × 4px, clamped to its minimum, so setting --m3-sys-density on any ancestor compacts everything inside it. Modern CSS, in depth

m3x is built on the current platform rather than around it. Every feature below is gated by its own @supports query and has a stated fallback, so the library degrades to a plainer version of the same design instead of a broken one. Each badge reads the query live — it tells you what the browser you are reading this in actually does.

Cascade layers

The compiled CSS opens with exactly this statement, and it is the library’s public contract:

@layer reset, bootstrap, tokens, bootstrap-compat, base, components, utilities, overrides;

bootstrap is reserved and left empty for a consumer’s real Bootstrap import — everything m3x defines outranks it. overrides is declared, always empty, and belongs to you. Each layer that carries component chrome splits into own and rules: the shared box-ownership rule sits in own, the component rules in rules, and a rule you write directly into the parent layer beats both.

Registered custom properties

Every colour role is registered with @property as a <color>, every shape step as a <length>, and the icon fill axis as a <number>. Typing them makes them interpolable: a theme change can be transitioned, a corner can spring, and an outlined icon can fill on select.

click — --m3-icon-fill animates 0 → 1

light-dark()

Each role is declared once, with both scheme values inline, and color-scheme alone decides which applies. [data-theme] and Bootstrap’s [data-bs-theme] just set color-scheme — there is no second block of dark overrides to keep in sync.

Without it: a static sRGB tier plus a prefers-color-scheme block ships first and is simply not overridden.

Relative color syntax

Where oklch(from …) works, all nine tonal ramps are derived from --md-seed at runtime, so retheming is one declaration. The seed picker in the header does exactly that — try it.

:root { --md-seed: teal; } rethemes both vocabularies, no rebuild

Without it: the build-time palettes stay in force; the seed picker does nothing and the compiled theme is unchanged.

color-mix()

Every state layer, every disabled treatment, every subtle border and every opacity utility is a color-mix() in sRGB. The build contains no rgba() or hsla() at all, which is what lets a token stay a token all the way to the pixel.

@scope

Three jobs: donut slots (a card’s content region is scoped so component rules stop at the slot), low-specificity internals, and the token islands below. There is no feature query for an at-rule, so an unsupporting browser drops these blocks wholesale — which is why every one of them is a refinement, never load-bearing structure.

See Token islands.

:has()

Parent-aware styling with no script: an open popover is read as :has(:popover-open), a split button’s menu picks the leading action through hidden radios, and a colour-swatch button follows the checked swatch through one rule per colour.

Corner geometry (corner-shape)

--m3-sys-corner-shape

M3’s second shape axis. The scale above says how big a corner is; the corner family says how it is drawn, and Material’s spec has two — rounded and cut (Android exposes them as shapeCornerFamily). CSS now has the property, so --m3-sys-corner-shape carries the keyword (round for rounded, bevel for cut) and the box-ownership rule applies it to every piece of chrome — so a host stylesheet cannot re-cut the library’s corners either. The radii are the same radii, so where the property is unsupported the row below simply draws rounded corners: the fallback needs no second code path. Controls that are round by identity pin themselves to round, because a bevel on a radius that is half the box turns a circle into a diamond.

Masks, conic gradients, clip paths

Progress indicators and the slider are drawn, not assembled: the linear track paints on a pseudo-element so the M3 gap can be cut without masking the bar inside it, the circular indicator is a conic gradient with transparent gap stops, and the slider’s handle clips its own gap ring with a clip-path. No SVG, no extra elements.

Form state selectors

:user-invalid means “invalid after the user has had a go”, so a required field is not red before it is touched. Type something into the field below and clear it. :open flips a select’s chevron while its picker is showing. .is-invalid is emitted byte-identical to :user-invalid for Bootstrap parity.

accent-color

Native controls m3x does not repaint — a date input’s picker, a file input’s button, the text selection — still take the theme, because accent-color is inherited from the root and re-inherited by every component.
